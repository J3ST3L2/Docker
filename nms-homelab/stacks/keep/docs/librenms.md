# LibreNMS -> Keep

Keep includes a native LibreNMS provider. It can read LibreNMS alerts through the LibreNMS API and receive pushed alerts through a webhook.

## 1. Connect the LibreNMS provider in Keep

In Keep:

1. Open **Providers**.
2. Find **LibreNMS**.
3. Configure:
   - LibreNMS URL
   - LibreNMS API token
4. Validate the provider.

For the home environment, use the URL of the existing LibreNMS instance and create a dedicated API token rather than reusing an unrelated credential.

## 2. Create a webhook API key in Keep

In Keep:

1. Open **Settings**.
2. Open **Users and Access** -> **API Keys**.
3. Create a key with the **webhook** role.
4. Store it in the LibreNMS transport. Do not commit it to Git.

## 3. Add a second LibreNMS transport

Leave the existing Slack transport enabled.

In LibreNMS:

1. Open **Alerts** -> **Alert Transports**.
2. Create an **API** transport.
3. Method: `POST`.
4. Use the webhook URL shown by the Keep LibreNMS provider.

The expected self-hosted base endpoint is:

```text
http://10.20.60.15:8180/alerts/event/libre_nms
```

If Keep shows a URL containing a `provider_id` query parameter, use the exact URL generated by Keep.

Add this HTTP header:

```text
X-API-KEY: <KEEP_WEBHOOK_API_KEY>
```

Set the request body to JSON. This trimmed payload carries the fields we actually care about for the first home workflow:

```json
{
  "title": "{{ $title }}",
  "hostname": "{{ $hostname }}",
  "device_id": "{{ $device_id }}",
  "sysDescr": "{{ $sysDescr }}",
  "sysName": "{{ $sysName }}",
  "os": "{{ $os }}",
  "type": "{{ $type }}",
  "ip": "{{ $ip }}",
  "display": "{{ $display }}",
  "version": "{{ $version }}",
  "hardware": "{{ $hardware }}",
  "serial": "{{ $serial }}",
  "location": "{{ $location }}",
  "description": "{{ $description }}",
  "uptime": "{{ $uptime }}",
  "alert_id": "{{ $alert_id }}",
  "rule_id": "{{ $rule_id }}",
  "severity": "{{ $severity }}",
  "rule": "{{ $rule }}",
  "name": "{{ $name }}",
  "timestamp": "{{ $timestamp }}",
  "state": "{{ $state }}",
  "msg": "{{ $msg }}"
}
```

## 4. Scope the rollout

Do not make the Keep transport global yet.

Attach it to one test alert rule while the current Slack transport remains active.

Expected test flow:

```text
LibreNMS
   +--> existing Slack webhook
   |
   +--> Keep --> Keep alert inbox
```

After the Keep -> Slack workflow is enabled:

```text
LibreNMS
   +--> existing Slack webhook
   |
   +--> Keep --> formatted Slack alert
```

## 5. What Keep normalizes

The Keep LibreNMS provider maps LibreNMS alert state to firing/resolved/acknowledged, maps LibreNMS severity to Keep severity, and records the source as `libre_nms`.

That source value is what the example workflow uses to avoid firing on unrelated alerts.
